Python 3.11+FastAPIReact 19 + ViteUbuntu 22.04 工站2026-08-06

1. 系统概览

控制中心由 FastAPI 后端、React 静态页面、SQLite 数据目录和工站 Agent 组成。生产模式下，后端同时提供页面、API 与 WebSocket。

8080页面 / API / WebSocket
8088Nginx 局域网入口
8081数据采集代理
22 / 9090工站 SSH / FSM
  • 正式入口：http://127.0.0.1:8080
  • 开发入口：http://127.0.0.1:5173，只用于 Vite 调试
  • 数据、数据库和生成的 Nginx 配置默认位于 data/

2. 首次安装与快速启动

在项目根目录执行，要求 Python 3.11 或更高版本。

安装后端

python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -e '.[test]'
cp .env.example .env

构建前端

cd frontend
npm install
npm run build
cd ..

启动

.venv/bin/station-monitor-server

浏览器访问 http://127.0.0.1:8080。默认账号 admin，默认密码 040712。

首次登录后立即修改密码默认密码仅用于初始化；开启互联网访问前，系统会检查管理员密码强度。

3. 配置与 API 登录

配置从项目根目录 .env 读取，不要提交真实密码、SSH 凭据或共享密钥。

变量用途建议
MONITOR_HOST / PORT后端监听配合 Nginx 时保持 127.0.0.1:8080
MONITOR_ADMIN_USERNAME / PASSWORD控制中心登录生产使用强密码
MONITOR_AGENT_SHARED_SECRETAgent 认证用 openssl rand -hex 32 生成，各端一致
MONITOR_PUBLIC_AGENT_URLAgent 回连工站可访问的 ws 或 wss 地址
MONITOR_ACQUISITION_BASE_URL采集上游默认 http://192.168.215.158
机械臂、数采、复位、归零命令工站控制按实际软件路径和用户权限修改
MONITOR_RETENTION_DAYS日志保留默认 30 天

除 /api/auth/login 外，所有 /api/* 请求都需要 HttpOnly Cookie：

curl -sS -c /tmp/wm.cookie -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"040712"}' \
  http://127.0.0.1:8080/api/auth/login

curl -sS -b /tmp/wm.cookie http://127.0.0.1:8080/api/health
curl -sS -b /tmp/wm.cookie http://127.0.0.1:8080/api/stations

4. 后台运行与开机启动

推荐创建 systemd 服务，按实际用户和路径修改：

[Unit]
Description=Workstation Monitor
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=zhangxin
WorkingDirectory=/home/zhangxin/桌面/Reily/workstation-monitor
EnvironmentFile=/home/zhangxin/桌面/Reily/workstation-monitor/.env
ExecStart=/home/zhangxin/桌面/Reily/workstation-monitor/.venv/bin/station-monitor-server
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target

保存为 workstation-monitor.service 后：

sudo install -m 0644 workstation-monitor.service /etc/systemd/system/workstation-monitor.service
sudo systemctl daemon-reload
sudo systemctl enable --now workstation-monitor.service
sudo systemctl status workstation-monitor.service
journalctl -u workstation-monitor.service -f
不要误判当前状态进程正在运行不代表已经安装同名 systemd unit；必须先安装服务文件。

5. 网络、Nginx 与远程访问

页面会查询本机 IPv4 并生成 data/workstation-monitor-nginx.conf。8088 转发控制中心，8081 转发数据采集。

ip -4 addr show
ss -ltnp | grep -E ':(8080|8081|8088)\b'

sudo cp data/workstation-monitor-nginx.conf /etc/nginx/conf.d/workstation-monitor.conf
sudo nginx -t
sudo systemctl reload nginx
提示 sudo 需要密码网页无法替你输入 sudo 密码。点击“开启说明”，或在服务器终端手动执行上述命令。

局域网

http://<本机IP>:8088，防火墙需允许 TCP 8088。

Tailscale

安装并登录后使用“开启远程访问”，接口为 POST /api/network/remote。

Cloudflare

安装 cloudflared 后使用“开启互联网访问”，并先设置强密码。

跨网络采集

换网失效通常是服务器无法访问上游 192.168.215.158，而非页面故障。

curl -I http://192.168.215.158/acquisition/project
ip route get 192.168.215.158

6. 工站接入与自动适配

  1. 工站推荐 Ubuntu 22.04，控制中心必须能访问 TCP 22。
  2. 填写工站名称、IP、SSH 端口和真实 Linux 凭据完成首次部署；密码不会保存。
  3. Agent 安装到 /opt/station-monitor，服务为 station-monitor-agent.service。
  4. 上线后逐项验证机械臂启停、数采启停、状态机复位、机械臂归零和任务控制。
自动重连与新增工站Agent 使用 Restart=always 和 RestartSec=3，离线重上线后自动回连。新增工站自动获得通用控制，已知 IP 会匹配任务配置。
sudo systemctl status station-monitor-agent.service
sudo journalctl -u station-monitor-agent.service -n 100 --no-pager
sudo systemctl restart station-monitor-agent.service

控制失败时查看悬浮弹窗中的退出码和 stderr，再检查对应日志。

7. 数据采集页面

点击“数据采集”后，后端自动登录采集系统并代理到对应项目，浏览器无需保存采集密码。

工站工站 IPproject_id
抽屉工站192.168.31.13184
下开门工站192.168.31.41185
右开门工站192.168.31.178186
上开门工站192.168.31.34187
左开门工站192.168.31.100182

目标路径统一为 /acquisition/sample?project_id=<编号>。新增工站可在添加或编辑窗口填写“数据采集项目 ID”；填写值优先于 IP 映射，现有五台工站未填写时仍自动使用上表映射。

页面空白或换网失效在控制中心服务器执行 curl -I http://192.168.215.158/acquisition/project。若不通，恢复现场路由、VPN 或网络；Nginx 无法代理自身不可达的上游。

8. SSH、终端与文件管理

支持交互终端、目录浏览、SFTP 上传/下载、常见文件预览和网络恢复后的自动重连。

不要混淆账号SSH 使用目标工站 Linux 用户名和密码，不是控制中心 admin / 040712。
ping -c 3 <工站IP>
nc -vz <工站IP> 22
ssh -vvv <用户名>@<工站IP>
# 工站本机
sudo systemctl status ssh
  • 单文件上传、下载和预览限制为 20 MB。
  • 目录访问受 SSH 用户权限限制。
  • 文本、图片、PDF 可直接预览；二进制文件建议下载。

9. 日志与告警

日志默认只显示当天记录并按时间倒序排列；机械臂、数据采集和任务动作分开筛选，支持下载、清空和批量删除。

来源文件用途
机械臂arm_app.log启动、驱动和控制异常
数据采集collection.log采集服务 journal
采集任务task-actions.log任务命令与结果
告警批量删除删除会作用于持久化数据。操作后刷新验证；如仍出现，检查后端响应和数据库写权限。

默认保留 30 天，由 MONITOR_RETENTION_DAYS 控制。

10. 状态机监控

状态机页面为 frontend/public/fsm_debug_ui.html，随项目静态资源启动并持续监听。访问格式：

http://127.0.0.1:8080/fsm_debug_ui.html?target=http://<工站IP>:9090

页面无数据时检查 Agent、工站 TCP 9090、FSM 进程和浏览器 Network/Console。

curl -v http://<工站IP>:9090/
nc -vz <工站IP> 9090

代码验证

上线验收

  • 登录、退出和修改密码正常
  • 在线工站优先显示，掉线重连后状态恢复
  • 机械臂、数采、复位和归零均返回明确结果
  • 采集页自动登录并匹配正确项目
  • SSH 终端、上传、下载和预览正常
  • 当天日志倒序显示且来源可切换
  • 告警批量删除后刷新不再出现
  • FSM 持续更新，桌面和手机布局无溢出

备份

至少备份 data/ 和部署机的 .env；后者含敏感信息，应加密保存。

sudo systemctl stop workstation-monitor.service
tar -czf workstation-monitor-data-$(date +%F).tar.gz data
sudo systemctl start workstation-monitor.service

12. 常见故障排查

现象优先检查处理方向
控制中心打不开进程、8080/8088、服务日志启动后端，检查 Nginx upstream
登录后返回登录页Cookie、时间、API 响应清理 Cookie，统一域名
采集页空白到 192.168.215.158 的路由恢复现场网络/VPN，检查 8081
SSH 失败IP:22、Linux 凭据、sshd勿用控制中心 admin，查防火墙
Agent 离线journal、回连 URL、共享密钥修正后重启 Agent
控制按钮失败弹窗、命令路径、权限在工站用相同用户复现
Nginx 未启用nginx -t、sudo服务器终端手动复制并 reload
FSM 无数据9090、FSM 进程、target恢复服务或修正地址
systemctl status workstation-monitor.service
journalctl -u workstation-monitor.service -n 200 --no-pager
ss -ltnp | grep -E ':(22|8080|8081|8088|9090)\b'
nginx -t
curl -I http://127.0.0.1:8080/
curl -I http://192.168.215.158/acquisition/project
