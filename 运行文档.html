01系统概览

控制中心同时提供管理页面、REST API 和实时 WebSocket；工站 Agent 负责采集状态、跟踪日志并执行白名单控制命令。

组件职责

组件目录/入口职责

02环境准备

  • Python 3.11 或更高版本。
  • Node.js 18+ 和 npm；仅前端构建/开发需要。
  • 控制中心推荐 Linux；自动部署目标工站必须是 Ubuntu 22.04。
  • 真实工站场景：控制中心能访问工站 SSH，工站能访问 Agent 回连地址。
  • 可选：Nginx、Tailscale、cloudflared、有效 TLS/mTLS 证书。

安装 Python 环境

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e ".[test]"

构建前端

cd frontend
npm ci
npm run build
cd ..
为何必须构建？生产入口由 FastAPI 托管 frontend/dist。目录不存在时后端 API 可以运行，但管理界面不会被提供。前端代码变更后也要重新构建。

03首次启动

  1. 生成本地配置

    cp .env.example .env

    编辑 .env。至少设置管理员强密码和 Agent 长随机共享密钥。

  2. 启动控制中心

    .venv/bin/station-monitor-server

    默认监听 127.0.0.1:8080。

  3. 执行健康检查

    curl -sS http://127.0.0.1:8080/api/health
ss -ltnp | grep ':8080'

  4. 打开管理页面

    访问 http://127.0.0.1:8080。API 文档位于 /docs。

  5. 可选：启动五工站模拟器

    .venv/bin/station-monitor-simulator \
  --server http://127.0.0.1:8080 \
  --count 5 \
  --secret change-me-before-production

    --secret 必须与服务端 MONITOR_AGENT_SHARED_SECRET 一致。

默认凭据只用于初始化.env.example 中的账号、密码、共享密钥、采集凭据和 IP 都是示例或现场默认值。投入使用前必须逐项核对并更换。

04运行模式

生产静态模式

先执行 npm run build，再运行后端；统一通过 8080 或 Nginx 8088 访问。

前端开发模式

后端运行在 8080，Vite 运行在 5173，并自动代理 /api 与 /ws。

模拟演示模式

控制中心加模拟器，不需要机械臂硬件，适合页面联调和演示。

真实工站模式

通过 SSH 部署 Agent，验证 WebSocket 回连、SDK、ROS、systemd 和日志权限。

前端开发命令

# 终端 1
.venv/bin/station-monitor-server

# 终端 2
cd frontend
npm run dev

# 浏览器
http://127.0.0.1:5173

模拟器参数

参数默认值说明
--serverhttp://127.0.0.1:8080控制中心 HTTP 地址，模拟器会转换为 Agent WebSocket。
--count5虚拟工站数量，可选 1～5。
--secret初始化示例值必须匹配服务端共享密钥。

05配置说明

服务端使用 pydantic-settings 加载项目根目录 .env，变量统一以 MONITOR_ 开头。修改后重启服务。

基础与安全

变量代码默认值说明
MONITOR_HOST127.0.0.1监听地址。经 Nginx 暴露时通常保持环回地址。
MONITOR_PORT8080控制中心端口。
MONITOR_DATA_DIRdata数据库、日志和生成配置目录。
MONITOR_RETENTION_DAYS30日志、审计和已恢复告警保留时间。
MONITOR_ADMIN_USERNAMEadmin管理页面账号。
MONITOR_ADMIN_PASSWORD初始化值必须修改；临时公网访问要求至少 12 位。
MONITOR_AGENT_SHARED_SECRET初始化值Agent 注册密钥，服务端与 Agent 必须一致。
MONITOR_ALLOW_INSECURE_AGENTStrue生产环境应设为 false 并配置 mTLS。
MONITOR_PUBLIC_AGENT_URLws://127.0.0.1:8080/ws/agent自动部署时写入 Agent 的回连地址。
MONITOR_HEARTBEAT_TIMEOUT_SECONDS10Agent 心跳超时阈值。

告警、采集与控制

变量组用途
MONITOR_CPU_WARNING_PERCENT / CRITICALCPU 告警阈值，默认 85% / 95%。
MONITOR_TEMPERATURE_WARNING_C / CRITICAL_C可选温度告警阈值。
MONITOR_SMTP_* / MONITOR_ALERT_EMAIL可选 SMTP 邮件告警。
MONITOR_ACQUISITION_*外部采集系统地址和自动登录凭据。
MONITOR_*_UNIT机械臂、采集、回零和状态复位 systemd 单元。
MONITOR_*_COMMANDSDK、任务、回零、状态复位和采集命令。
MONITOR_LOG_PATHSAgent 跟踪的日志文件路径。
MONITOR_COMMAND_WORKDIR工站控制命令工作目录，默认 /var/log/airbot。
配置名称以源码为准新增或完整配置项可查看 station_monitor/server/config.py、station_monitor/agent/config.py 和 .env.example。

06后台运行与开机启动

仓库提供工站 Agent 的 systemd 文件；控制中心可按部署路径自建服务。下面是控制中心示例，请替换用户和绝对路径。

[Unit]
Description=AIRBOT Workstation Monitor
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=<运行用户>
WorkingDirectory=<项目绝对路径>
ExecStart=<项目绝对路径>/.venv/bin/station-monitor-server
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
sudo install -m 0644 workstation-monitor.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now workstation-monitor.service
sudo systemctl status workstation-monitor.service
sudo journalctl -u workstation-monitor.service -f
权限要求运行用户必须能读取项目和 .env，并能写入 data/。若页面需要自动启用 Nginx，相关 sudo -n 命令还需单独授权；不要给服务无边界的 sudo 权限。

升级流程

sudo systemctl stop workstation-monitor.service
# 备份 data/ 与 .env
source .venv/bin/activate
pip install -e ".[test]"
cd frontend && npm ci && npm run build && cd ..
.venv/bin/python -m compileall -q station_monitor
.venv/bin/pytest -q
sudo systemctl start workstation-monitor.service

07工站 Agent 接入

自动接入流程

  1. 控制中心使用用户填写的工站 Linux 账号进行一次 SSH 连接。
  2. 检查目标系统为 Ubuntu 22.04，并安装缺失的 Python 依赖。
  3. 把 Agent 源码安装到 /opt/station-monitor。
  4. 生成 /etc/station-monitor/agent.json。
  5. 安装并启用 station-monitor-agent.service。
  6. Agent 通过 MONITOR_PUBLIC_AGENT_URL 回连，发送心跳、遥测与日志。
凭据处理SSH 密码用于当前接入请求，不写入数据库。数据库记录工站 SSH 用户、端口和认证/可达状态。

接入前检查

ping -c 3 <工站 IP>
nc -vz <工站 IP> 22
ssh <Linux 用户>@<工站 IP>
curl -I <Agent 回连地址对应的 HTTP/HTTPS 入口>

Agent 配置示例

{
  "station_id": "站点 UUID",
  "station_ip": "192.168.31.13",
  "server_url": "wss://monitor.example:8443/ws/agent",
  "secret": "与服务端一致的共享密钥",
  "robot_unit": "airbot-robot.service",
  "collection_unit": "airbot-collection.service",
  "ros_domain_id": 0,
  "joint_topic": "/joint_states",
  "temperature_topics": [],
  "log_paths": ["/userdata/storage/arm_app/last/log/arm_app.log"]
}

Agent 运维

sudo systemctl status station-monitor-agent.service
sudo systemctl restart station-monitor-agent.service
sudo journalctl -u station-monitor-agent.service -n 200 --no-pager
sudo cat /etc/station-monitor/agent.json
已知工站任务适配源码对五个已知现场 IP 配置了专用开/关任务命令；其他 IP 使用 .env 的通用任务命令。新增现场型号时应先验证命令、类别、主机参数与状态机选项。

mTLS 建议

deploy/nginx-agent-mtls.conf 提供 8443 示例：Nginx 验证客户端证书、代理 /ws/agent 并设置 X-SSL-Client-Verify。启用后设置：

MONITOR_ALLOW_INSECURE_AGENTS=false
MONITOR_PUBLIC_AGENT_URL=wss://<控制中心地址>:8443/ws/agent

08日常操作

工站总览

观察在线、Agent/SSH、进程、CPU、关节、温度和活动告警。

进程控制

启动、停止、重启机械臂和采集，执行任务开关、回零与复位。

日志与告警

按日期、来源、级别筛选；下载/清理日志，确认或删除告警。

SSH 与文件

使用目标工站 Linux 凭据建立终端和文件会话。

控制安全边界

  • 结构化进程控制只接受服务端定义的目标与动作。
  • Agent 的普通进程控制使用白名单；回零、复位和任务使用配置中的固定命令。
  • SSH 终端本身具备目标账号的完整权限，应单独限制账号、来源 IP 和审计访问。
  • 批量命令模型最多接受 5 个工站 ID。

日志与告警

类别默认行为运维提示
日志索引写入 SQLite，并按日期/工站/来源分页查询。页面可按机械臂、采集与级别筛选。
日志原文写入 data/logs/.../*.ndjson。支持下载和按选择删除。
告警CPU、温度、进程、心跳与错误日志可触发。支持确认、全部确认和批量删除。
保留清理后台每小时运行一次，默认保留 30 天。清理前先做数据备份。

数据采集与 FSM

工站可关联 acquisition_project_id。控制中心使用配置的采集账号向上游登录，并将浏览器引导到对应项目。FSM 调试页面位于：

http://127.0.0.1:8080/fsm_debug_ui.html?target=http://<工站IP>:9090
不要混淆账号控制中心管理员账号用于网页登录；SSH 使用目标工站 Linux 账号；数据采集代理使用 MONITOR_ACQUISITION_* 凭据。三者互不通用。

09数据、接口与端口

持久化目录

路径内容
data/monitor.db工站、最新遥测、告警、命令任务、日志索引和审计记录。

核心接口

类型路径用途

REST/api/stations工站列表、创建、更新、删除、接入和重连。

REST/api/logs分页查询、错误日志、文件、下载与清理。
REST/api/network/*Nginx、Tailscale 与临时公网访问。

10局域网、远程与互联网访问

局域网 Nginx

页面会检测 8088 和 8081，并生成 data/workstation-monitor-nginx.conf：

  • 8088：代理控制中心 8080，包含 WebSocket Upgrade。
  • 8081：代理外部数据采集上游。

自动安装和启用依赖无交互 sudo -n。若失败，手动执行：

sudo install -m 0644 data/workstation-monitor-nginx.conf \
  /etc/nginx/conf.d/workstation-monitor.conf
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl reload nginx

Tailscale 私网

tailscale ip -4
# 若未连接
sudo tailscale up

连接成功后使用 http://<Tailscale-IP>:8088。这仍是 HTTP，机密性依赖 Tailscale 网络；按组织策略配置 ACL。

临时公网隧道

后端优先启动 Cloudflare Quick Tunnel 指向 127.0.0.1:8088，失败后尝试 localhost.run。返回地址是临时地址，服务重启后可能变化。

公网暴露风险该页面包含工站控制、SSH 终端和文件能力。临时隧道只适合短时受控演示，不应用作生产发布方式。后端会要求管理员密码至少 12 位，但这不等于完整安全加固。

采集上游连通性

curl -I "$MONITOR_ACQUISITION_BASE_URL"
ip route
ss -ltnp | grep -E ':(8080|8081|8088)'

11生产安全清单

  • 更换管理员密码，使用至少 12 位随机密码
  • 更换 Agent 共享密钥
  • 设置 MONITOR_ALLOW_INSECURE_AGENTS=false
  • 为 Agent WebSocket 配置 TLS 与客户端证书
  • 控制中心仅监听环回或受控管理网
  • 限制 22、8080、8081、8088、8443 的来源地址
  • SSH 使用专用低权限账号和密钥认证
  • 不要提交 .env、Agent secret 或证书私钥
  • 限制 systemd 服务文件和 data/ 的文件权限
  • 启用 SQLite、日志、审计和配置备份
  • 谨慎使用临时公网隧道
  • 核对固定控制命令及其运行用户权限
自动化与 sudo网页启用 Nginx 和 SSH 接入可能需要系统权限。仅授权具体命令和具体目标路径，避免给 Web 服务用户开放任意 sudo。

13故障排查

推荐顺序：进程 → 端口 → 本机 HTTP → 网络路由 → 认证/密钥 → 业务命令与权限。

现象优先检查处理方向
控制中心打不开服务日志、8080、健康接口修复启动错误，确认 .env 与 data/ 权限。
8088 返回 5028080 是否监听、Nginx upstream先启动后端，再执行 nginx -t 和 reload。
登录后仍回登录页登录 API、Cookie、域名与浏览器时间统一访问域名，清理旧 Cookie，检查服务端时间。
模拟器无法注册共享密钥、服务端地址让 --secret 匹配服务端配置。
Agent 离线Agent journal、回连 URL、密钥、mTLS从工站测试地址，修正配置后重启 Agent。
SSH 接入失败IP:22、Linux 凭据、Ubuntu 版本勿使用网页 admin；检查 sshd、防火墙和权限。
控制命令失败systemd 单元、可执行文件、工作目录使用 Agent 运行用户在工站复现同一固定命令。
采集页空白采集上游网络、凭据、project_id恢复现场路由/VPN，验证上游登录。
FSM 无数据工站 9090、target 参数、FSM 进程测试工站端口并修正页面目标 URL。
日志不更新Agent 日志路径、文件权限、WebSocket核对 log_paths，查看 Agent journal。
Nginx 自动启用失败sudo -n、安装状态、配置语法按生成配置在服务器终端手动安装并 reload。
公网地址失效隧道进程、DNS、网络出口临时隧道地址会变化；重新开启并检查状态。
